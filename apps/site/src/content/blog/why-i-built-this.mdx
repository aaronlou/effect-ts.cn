# 为什么我要做这个 Effect 中文社区

> 这篇是原创随笔，不是文档。它记录一个想法怎么变的：我原本以为重点是翻译，做完才发现不是。

## 为什么值得关注 Effect

先说服你它值得花时间。

你写 TypeScript 后端，最后总会自己手写这几样东西：错误怎么分类、怎么往上传递；依赖怎么注入、测试怎么替换实现；并发怎么起、怎么取消、资源怎么释放；重试、超时、日志怎么统一。

这些全是**运行时的关注点，类型系统管不到**。所以每个项目各写一套，谁写谁不一样，换个人接手就得重读一遍。

Effect 做的事，是把它们搬进类型：一个 `Effect<成功, 失败, 依赖>` 里，失败和依赖都是类型的一部分。测试时换一个 Layer，业务代码一行不用改；并发有 Fiber、资源有 Scope、重试有 Schedule，不用自己搓。

但它是有明确适用面的一把重锤。**代价我必须说清楚：Effect 不好学**——概念多、报错长、一开始写得很别扭。写个小脚本完全不值得。只有当项目变大、参与的人变多，上面那四件事真的开始变成主要成本时，它才开始回本。

顺便一个我实测出来的事实：现在最火的开源编码 Agent（opencode，20 万 star）核心就是用 Effect 写的——它 40 个包里有 21 个运行时依赖 Effect。这不是宣传，是我为了做另一个页面逐个包读 `package.json` 数出来的。

## 我原以为重点是翻译

老实说，动手时的第一版想法很朴素：官方文档全英文，v3 和 v4 两套并行容易看串，报错又是一大段类型推导——那就把它们翻成中文。

于是我把它翻完了：234 页，v4 110 页 + v3 124 页。

然后你猜怎么着——**这件事现在几乎不值钱了**。任何一个人把一段英文文档丢给模型，几秒钟就能得到一份不错的中文。翻译是一次性的劳动，而 AI 把一次性劳动的价格压到了接近零。

如果这个站的价值就等于"234 页中文"，那它没有存在的必要。

## 那真正难的是什么

把文档翻完只解决了一半问题。剩下那一半，是**怎么让人敢信它**。

技术文档里，一个说错的答案比不回答更糟：你会照着它去写代码，然后在半小时后卡在一个根本不存在的 API 上。所以真正要解决的是三件事：

### 一、答案必须能被查证，而不是被相信

站内 AI 的每一条引用，都对应一个可以单独打开的记录：它给出引用的**中文原文片段**、**内容指纹**、**上游英文原文的链接（锁定在翻译时记录的那次 commit 上）**，以及**这篇译文是否已经落后于上游**。

也就是说：你不需要相信我说的是对的，你可以自己去核对。引用不是修辞，是可取证的事实。

### 二、它必须会说"不知道"

站内没有依据时，它直接拒答，不编。

而且会区分两种"没有"：「文档里确实没写这件事」和「这一页中文还没翻译」。后者会告诉你原文在哪、可以去认领翻译。这个区别看着小，但它决定了你拿到的是"帮我解决"还是"帮我到这儿"。

### 三、翻一次容易，不漂移很难

AI 能把 234 页翻完。但上游每天都在动——官方改了代码示例、调了章节顺序，你这边如果没人跟着，几个月后这份译文就会悄悄变成错的。

所以这件事的重心其实不在翻译，在**同步**：每天比对上游、给落后的页面打标记、并且用门禁保证译文里的代码块与上游**逐字节一致**（注释里的代码也一样）。这部分没有任何捷径，只能靠工程把它变成自动的。

## 做的过程中踩到的坑

这部分也许比结论更有用。为了做站上那个「生态项目榜」，我写了个采集器去 GitHub 上找"用 Effect 写的 AI 项目"。它教给我的事，比榜单本身有价值。

**「声明了」不等于「在用」。** 我一开始的判据是"`package.json` 里有 effect 就算"。结果撞了一堆反例：

- `zod`（4.3 万 star）确实依赖 Effect——但只在 `packages/bench/` 里，那是它拿 Effect 当**性能对比的对手**；
- `vercel/ai`（2.6 万 star）只在 `examples/` 里用；
- 反过来，我以为 `sst`（2.6 万 star）是 Effect 项目，逐个读完它 **195 个** `package.json`，一个都不依赖；
- 更微妙的是 `supermemory-mcp`：它在 `dependencies` 里老老实实写了 `effect`，但**全仓库没有任何一个文件 import 它**。

所以我最后的判据是两条：**运行时依赖 + 全仓至少有一个文件真的 import 它**。少一条都会收进错的东西。

**最危险的不是报错，是失败被伪装成结论。** 有两次，下载项目源码失败（仓库太大、超时），而我的代码把"没扫到文件"当成了"这个项目没用 Effect"——19k star 的 `eliza` 和 3.6k star 的 `wa-automate` 就这样被静默淘汰了。它们在榜单上消失时，没有任何报错。

修法是把"未知"和"否"彻底分开：读不到就记为**未知**，单独列出来，绝不混进淘汰名单。这件事让我改掉了好几个地方——**一个系统里最危险的错误，是那种看起来像正常结果的错误**。

**本地全绿、CI 全红。** 还有一个只有上了 CI 才暴露的问题：v3 和 v4 的同一个页面**标题完全一样**（都叫《为什么选择 Effect？》），而我的一段排序逻辑没给出全序——于是结果取决于文件系统的遍历顺序。在我机器上是 v4 赢，在 CI 的 Linux 上变成 v3 赢。门禁在本地绿、在 CI 红，一度让我以为是自己看错了。

## 现在有什么，还没有什么

已经能用的：

- **官方文档 234 页全量中文**（v4 + v3），每页标注翻译时的上游基线，未翻译的页面也诚实标注而不是留死链；
- **问答与报错诊断**：答案只从站内译文合成，每句引用可点回原文，没依据就拒答；
- **生态项目榜**：26 个用 Effect 写的 AI / Agent / LLM 项目，标注"Effect 渗透度"和"该读哪一块"；
- 给 AI 工具用的入口：`/llms.txt`、每页的 `.md`、以及一个 MCP server，让 Agent 能直接消费这份中文知识。

还没有的，也直说：

- **真正的社区还没有建起来**。没有讨论区、没有投稿流程、微信群入口还是空的。这一篇发出来，也是想先找到人。
- 站上所有的译文目前是**机器起草 + 机器校验**（术语黑名单、代码块逐字节比对、引用可解引用都是自动门禁），**还没有经过人类逐篇精读**。这一点我不想含糊过去——它意味着可用，但不意味着没有错。
- 广告位做了但默认关闭。理由很简单：真正关心这个库的人会装广告拦截器，而塞广告会同时伤到"这是个可信的中文文档站"这件事。

## 来搭把手

如果你在读这段话，说明你至少对 Effect 有点兴趣。三件事随便挑一件：

1. **挑错**：翻译有错、引用对不上、某个答案答得不对——都是最有价值的反馈，[提 issue](https://github.com/aaronlou/effect-ts.cn/issues) 就行；
2. **认领翻译**：站上还有页面落后于上游，译者指南在仓库里；
3. **告诉我你为什么没开始学 Effect**：是文档门槛、是没时间、还是觉得用不上？这个答案对我比 star 重要。
